# Password-free USB play

Normal **Connect Board** inventories physical USB devices, then connects the selected UNO Q (the sole ready device is selected after the explicit click). It never loads saved Board records, installation keys or Keychain, and never falls back to Bonjour/Wi-Fi. Practice, including cancellation during connection, remains available. The native result contains only an opaque handle and public Board UUID.

## Authority and lifetime

1. Fixed native `usb_play_boards` / `connect_usb_play` IPC accepts only an explicit serial, not paths, code, addresses or tokens. Fresh loopback ADB `usb:` evidence and the existing UNO Q/Debian/SoC inspection precede every bootstrap/proof.
2. The embedded `python3 -B` helper accepts only `begin` or `refresh` JSON on private stdin. It reads the fixed owned app configuration/public certificate, verifies all six runtime files against compiled hashes before importing baseline/selected-slot code, and never imports an unverified or frontend-selected module. No private Board key is read/exported. An unsupported/older source fails with a contextual one-time update instruction.
3. Physical USB issues a random one-use 30-second grant; `POST /v1/usb-sessions` consumes it over native pinned HTTPS through the fixed ADB `localfilesystem:/home/arduino/ArduinoApps/tinkercrew-companion/data/usb-play.sock` forward. The private Unix socket is 0600 inside owned 0700 data, bind-mounted across the supported official Docker layout. No installation/SSH registration is created. TLS hostname, certificate validity, stable Board UUID, boot identity and exact compiled runtime release remain checked.
4. Tokens have a distinct `usb1.` namespace. **Every** HTTP use, including hello, reads, control, commands and close, requires the private Unix listener. The TCP listener rejects USB credentials even from localhost or spoofed forwarded headers; persistent parent sessions still use TCP normally. HTTPS TLS authentication is not disabled. A live Board inspection found the official Docker bridge rewrites USB peer addresses, so IP-only loopback checks were rejected before rollout. ADB forwards TLS bytes to the protected filesystem socket instead; no network proxy or new exposed TCP port is trusted.
5. Board `usb-play.sqlite` holds only hashes/public IDs. Directory 0700, DB 0600, no symlinks/hardlinks; a separate runtime epoch invalidates grants/sessions on server restart, including exchange/restart races. Records also bind Board and kernel boot. Four pending grants and two concurrent USB sessions maximum; stale rows are pruned. Persistent Pairing, keys and unrelated apps are untouched.
6. Session expiry is 150 monotonic seconds; HTTP inactivity expires it after 60 seconds. A native weak-owner background worker checks the exact physical USB identity and renews only an existing, live session every 20 seconds. USB proof cannot resurrect an expired session or extend HTTP inactivity. Native authority fails closed after 90 seconds without successful physical proof or 50 seconds without gameplay requests. Slow proof does not serialize stale output/lease requests behind credential I/O. Failure requires explicit Connect again, never automatic enrollment/rearming.
7. Disconnect closes the session and drops only its owned forward. Late/cancelled UI connection results close their **specific handle**, never a newer controller. Unplug immediately breaks the USB transport; the unchanged Linux/MCU control watchdogs and output TTLs independently bound outputs. Stop is software, not a certified power disconnect.

Connecting never acquires an output lease. Creations still need explicit module-test/Run intent. Concurrent controllers cannot steal one another's lease. Maintenance can authenticate a trial-health reader, but still denies all output leases/commands; ending maintenance does not rearm.

## Parent path and migration

Saved installation Pairing remains unchanged for optional parent network/maintenance use, behind **Parent network connection — saved Pairing (optional)**. Loading those records is an explicit parent action and can require OS Keychain approval. No credentials are erased/migrated, no ACL changes, no plaintext credential files or diagnostic-helper impersonation.

A running compatible Companion is required. Existing supported installations need one guarded, parent-approved **Linux-only runtime update**; the six-file protocol and baseline contract are unchanged (`auth.py` was deliberately not changed). A physical operator can transfer the fixed bundle through existing bounded USB management, authenticate disarmed trial health with the new temporary USB grant, and finish using the job capability. This needs no persistent temporary installation or SSH key. The original fixed historical never-started profile repair remains separately pinned to its two original releases; its frozen test fixture must not evolve with current gameplay code. No reset, official firmware-capable start, OS update or whole-baseline migration is hidden in Connect.

## Evidence

Approved seams: real Companion HTTPS + temporary registry/clock, actual non-loopback and localhost TCP denial, private Unix TLS ingress, the fixed bootstrap with temporary exact runtime trees, native real-TLS adapter, UI/IPC and existing deployment interfaces. Tests use only generated fixture credentials, not user Keychain or real outputs. Automated tests and health200 are not physical module or family-play acceptance. Live rollout and actual native/GUI witnesses must be recorded separately; power-cycle/default-start and public release gates remain open.
