# Temporary USB play instead of Mac credential storage for normal play

The owner wants children to connect without Mac passwords or Keychain approval. Normal USB play therefore uses physically bootstrapped, short-lived native-memory credentials and pinned HTTPS; saved installation Pairing remains an optional parent-managed network/maintenance path. Unlike removing authentication or storing plaintext keys, this keeps bounded authenticated Commands while removing persistent Mac credentials from play.

USB credentials are accepted only on a private Unix TLS listener reached through a fixed ADB filesystem-socket forward; the LAN/TCP listener rejects them, including localhost requests. This remains reliable across the official Docker bridge, unlike source-IP checks. They are boot/process-bound, capped, expiring and renewable only with fresh physical USB proof. They create no installation/SSH registrations, grant no management authority and never enter frontend storage or logs. USB still requires one-time supported Board preparation and the running Companion; this is not an OS-login bypass or permission for arbitrary USB devices. The existing ADR-0001 separation between fixed management bootstrap and bounded gameplay remains intact, but persistent Pairing is no longer required for USB gameplay.
